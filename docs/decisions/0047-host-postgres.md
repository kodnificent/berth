# 0047. Host Postgres databases and one URL key

Status: accepted

## Context
A host Postgres server follows every rule MySQL does (design, Host Postgres): the server and login from main's `.env`, names and prefixes, what a berth owns, the record that decides what is dropped, `reset`, `status`, `list` and `doctor`. Names are cut to 63 bytes. A berth's own sessions must not block cleanup, and no session on any other database may be ended. `from = "env:DATABASE_URL"` reads the server, login and database from one URL, for MySQL and Postgres, and berth writes the berth's URL to that key. Until this record, everything host-database in `internal/cli` called `internal/mysql` directly, and the registry record had only `mysql`.

## Decision
- **Engine seam:** `internal/hostdb` holds what every engine shares: `Server`, `Login`, a `Conn` interface (list, create, drop, size, close), an `Engine` (name, `[state]` table, longest name, default port, `Open`) and a `Location` that reads the server and login from a `.env`, under a prefix or from one URL. `internal/mysql` and `internal/postgres` each export an `Engine`; `mysql.Server` and `mysql.Login` are aliases, so the dump, seed and snapshot code, which stays MySQL's, is unchanged. Code that needs more than the interface, the dump's table listing and the server's data directory, asks for the MySQL connection and gets nil on Postgres. The seam is as wide as create, list, drop, size, names and the record; a `template` copy can be added on the Postgres type alone.
- **Record:** `registry.Record` has `mysql` and `postgres`, both of type `HostDB`, at most one set, and `Record.DB()` returns whichever is. The engine is the key it is under, so a record written before Postgres support, with only `mysql`, reads, removes, prunes and resets as before, and an older berth that meets a `postgres` record ignores it rather than talking MySQL to a Postgres server. `HostDB` gains `url_key`, and each database `url`, true for the one main's URL names. `add` refuses, exit `1`, when the config now names the other engine than the record.
- **One server per project:** a config naming both `[state.mysql]` and `[state.postgres]` exits `5`. The clone state, command logs and status entries are keyed by database key, and two engines could share one.
- **Client:** `github.com/jackc/pgx/v5`, pure Go, as 0040 chose for MySQL, at v5.7.6, the newest that builds with the Go version `go.mod` names. One connection to the `postgres` maintenance database, `sslmode=prefer`, a 10 second connect timeout and two minutes per statement. Everything but the login goes in the connection string berth builds, so the `PG*` variables of the shell berth runs in can't point it at another host, port or database; the login is set on the parsed config, never in a string the driver quotes. Errors are scrubbed of the user and password as MySQL's are. A server older than 13 is refused when berth connects, since `DROP DATABASE … WITH (FORCE)` is 13's.
- **Names:** the same segment, prefix and candidate rules (0040), with the engine's longest name: 63 bytes on Postgres, 64 on MySQL. A cut source name ends on a character boundary, since a cut through a multibyte character is a name Postgres rejects. Every name is sent quoted, as Postgres folds unquoted ones to lowercase. Postgres silently cuts a longer name to 63 bytes, so `Create`, `Drop` and `Size` refuse any name over it: a drop must never act on the database the cut name happens to be.
- **Listing:** every database in `pg_database` apart from `postgres` and templates.
- **Create:** `CREATE DATABASE`, treating the server's "already exists" as done, since Postgres has no `IF NOT EXISTS` there.
- **Drops:** `DROP DATABASE IF EXISTS … WITH (FORCE)`, which ends the sessions on that database and on no other. Postgres lets a login end only its own role's sessions, so a session under another login makes the drop fail, and the record keeps the database for a retry, as for a server that is down. Teardown and reset check that the record owns each name again right before dropping it, whatever put the name on the list.
- **One URL key:** `from = "env:<KEY>"` without a star names a URL key. The URL is parsed with `net/url`; its errors are replaced by a fixed message, since the parser quotes the URL. Host and port come from it, the port defaulting to the engine's, the login from its user part, decoded. Its path must name one database, which must be the source of an entry in the config, or `add` exits `5`: unlisted, the berth would keep main's URL. With a prefix, that means a database under main's prefix: a key names the database under it, never one outside that shares its name. A URL naming more than one host, or whose query sets where the connection goes (for Postgres `dbname`, `database`, `host`, `hostaddr`, `port`, `service`, `servicefile` and `options`; for MySQL `database`, `dbname`, `host`, `port`, `socket` and `unix_socket`), exits `5` naming the key and the parameter, never its value, since the app's driver would follow it past the path berth rewrites. Other parameters, such as `sslmode`, are kept. The berth's URL is main's with only the path changed, by position in the string, so the login's percent-encoding and the query string are kept byte for byte.
- **Where the URL lives:** the record holds the key, never the URL, since it carries the login. `managedEnv` reads main's `.env`, then the berth's own, and takes the first URL that names the recorded server, so `status`, `env` and `exec` work with main's `.env` gone, and a main moved to another server never points a berth at it. The managed block, `exec` and `berth env` give the real URL, the value the app reads from `.env`, since `eval "$(berth env)"` must reach the same database; `status`, `env --json`, the shadowing report and `doctor` show it with the user, password and query string taken out. `remove` and `prune` read the login from the berth's URL, or from the shell's for an orphan, as 0040 does for the prefix keys.
- **doctor** in a berth also reports a URL key that names any database other than the berth's own for it, without printing the URL.

## Options considered
- Copying `databases.go` for Postgres: two copies of the naming, ownership and teardown rules would drift, and those rules are the guarantees.
- One record field with an `engine` inside: an older berth would read a Postgres berth as MySQL and talk the MySQL protocol to it.
- `lib/pq`: in maintenance mode, and it takes a whole connection string, so the login would pass through a string its errors may quote.
- pgx v5.12: needs Go 1.25, which would raise the Go version for every contributor and CI for this one dependency.
- `pg_terminate_backend` on the berth's databases before `DROP DATABASE`: a session can connect between the two, and `WITH (FORCE)` does both under the server's own lock.
- Allowing `[state.mysql]` and `[state.postgres]` together: the clone state and command logs are keyed by database key, so both engines' entries would have to be namespaced first; the design has no such project yet.
- Storing the berth's URL, or its non-secret parts, in the record: a query string may hold a password, and the design keeps credentials out of the record.
- Redacting only the password in what berth shows: the design keeps every credential berth reads out of its output, the user included, and a query string may carry `password=`.

## Evidence
`e2e/host_postgres_test.go`, against Postgres 13.22 and 18.1 in Docker with a login that is not a superuser, covers the prefix guarantee on Postgres, `remove` dropping a database the app is connected to while ending no session on another database, `remove` dropping only what the app created under the prefix, long names cut and still unique, MySQL-only strategies refused with exit `5`, `remove` and `prune` with main's `.env` deleted, and `reset` refusing when main names another server. `e2e/host_database_url_test.go` covers the URL key for MySQL and for Postgres. `e2e/host_postgres_strategies_test.go` covers `fresh`, `skip`, `none` with `doctor`'s warning and `command` with its variables, and walks the state directory and the output of every reporting command for the URL's login, with the URL exported in the shell too; it fails when the redaction is taken out. The host MySQL suites pass unchanged on the seam. Unit tests: `internal/hostdb` (encoded logins and query strings kept, a URL error never quoting the password, redaction), `internal/postgres` (`Drop` refuses a name Postgres would cut), `internal/cli` (a drop of a database the record doesn't own is refused) and `internal/config`.

## Undoing it
The client is `internal/postgres`; the seam is `internal/hostdb`; the URL key is `Location` there and `berthURL` and `redactEnv` in `internal/cli/databases.go`; the config is `HostDB` and `postgresRefusal` in `internal/config`. Records with `postgres` are ignored by code without it, which leaves those berths' databases on the server with nothing to drop them: remove those berths first, or drop their databases by the recorded prefix and names. Older code reads a record with `url_key` as having an empty `env_prefix`, looks for the login in keys with no prefix, which hold none berth can use, and keeps the berth; remove such berths before reverting. Folding the seam back into `internal/mysql` touches only `internal/cli` and the aliases.
